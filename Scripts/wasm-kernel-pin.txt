# The prebuilt wasm OCCT kernel this repo consumes, in one place every wasm script reads.
#
# The native side pins its kernel in Package.swift, as a binaryTarget url:/checksum: pair. The wasm
# side cannot: SwiftPM's binaryTarget takes an xcframework or a zip of one, never a bare static
# library, and there is no wasm equivalent. So the pin lives here, and Scripts/fetch-occt-wasm.sh
# is what resolves it.
#
# Format: comment and blank lines are ignored; every other line is KEY=value, with no quoting and
# no shell expansion. Parse it, do not source it: it is data, not code. Same rule as
# Scripts/wasm-toolchain-versions.txt, deliberately, so one parser reads both.
#
# WHAT IS IN THE ASSET
#
# A tar.gz of exactly two things, both produced by Scripts/build-occt-wasm.sh:
#
#   libOCCT-wasm.a        the combined archive, all 49 toolkits
#   occt-headers-wasm/    the flat header tree the bridge compiles against
#
# Both are gitignored build outputs (see .gitignore's `Libraries/` rules), which is the whole reason
# this file exists: before it, a consumer who resolved OCCTSwift by version got a checkout with
# neither, and the only route to a wasm build was a 69-minute local OCCT build plus a wasi-sdk and
# a Swift wasm SDK install.
#
# WHY IT HANGS OFF A KERNEL RELEASE TAG
#
# The asset is attached to the SAME release as the OCCT.xcframework built from the SAME patch set,
# so one release means one kernel, on both platforms. That is what makes the parity check below
# mechanical rather than a matter of remembering.
#
# THE RULE, AND IT IS THE ONE THAT WILL BE FORGOTTEN
#
# A repin of the native kernel that does not also rebuild and republish this asset leaves the two
# platforms on different kernels, silently, because nothing about a Swift build for macOS touches
# any of this. Scripts/check-wasm-kernel-parity.py is the gate for that, and it compares the patch
# set below against the one Package.swift enumerates. See okf/policies/pinned-kernel-patch-check.md
# for why a count alone is necessary and not sufficient.

OCCT_WASM_ASSET_URL=https://github.com/SecondMouseAU/OCCTSwift/releases/download/v4.0.0-kernel.4/libOCCT-wasm.tar.gz

OCCT_WASM_ASSET_BYTES=40257980

# --- what is inside it, for the parity gate ---
# The carried patches are Scripts/patches/NNNN-*.patch. FIRST and LAST are the numbers, not an
# assertion that every number between them exists: the gate reads the actual file list.
OCCT_VERSION=V8_0_1
OCCT_WASM_PATCH_COUNT=39
OCCT_WASM_PATCH_FIRST=0010
OCCT_WASM_PATCH_LAST=0052
# The WASI-only source changes, Scripts/patches-wasi/*.patch, which only build-occt-wasm.sh applies.
OCCT_WASM_WASI_PATCH_COUNT=11

# --- the acknowledged divergence, and what closes it ---
# THERE IS NO DIVERGENCE. Both kernels in v4.0.0-kernel.4 were built from one tree carrying all
# thirty-nine carried patches, in one sitting, which is what the retired acknowledgement below
# said would close it. The two ACKNOWLEDGED_* keys are deliberately absent rather than set to a
# zero or a nil: this field's own rule is that AGAINST is never a number to bump, so an
# acknowledgement that no longer acknowledges anything is deleted, not updated. Retired here:
#
#   v4.0.0-kernel.3 pinned 0043 (#2827) natively without rebuilding this 69-minute wasm asset,
#   so the browser returned the fabricated 0.0 from Face.volumeInertia(planeNormal:planeDistance:).
#   It was keyed to 31 native patches and expected the OCCT 8.0.2 rebuild to close it. 8.0.2 did
#   not ship, so the rebuild happened anyway (#3031) and closed it on 2026-10-03.
