# --- exact-equality baselines do not survive a different libm --------------------------------
# `Issue791ConvertCircleHelperTests` (Geom2d, 2 tests) and `Issue791ConvertSphereHelperTests`
# (Surface, 2 tests) each compare a computed pole against a hardcoded baseline with `==`,
# not a tolerance. The wasm build links WASILibc's math functions and the Apple build links Darwin's,
# and IEEE 754 does not pin the results of transcendentals to the last bit, so `sin`/`cos` on the two
# platforms legitimately differ in the final places and an exact comparison cannot hold across both.
#
# Nothing is wrong with the geometry here and nothing is wrong with the port. The tests are wrong to
# use `==` on a value derived through trigonometry, and the fix is a tolerance, which is a change to
# an Apple-platform test and so belongs in its own PR rather than this one. Listed rather than
# excluded because they are real failures a reader should see.
#
# `Issue196PolyHLRTests` is the same cause with a tolerance rather than an exact comparison, and it
# reached a wasm run for the first time under #2928. Its subject holds here: a coarser mesh really
# does draw fewer outline edges and more sharp ones, and both relational assertions pass, as do both
# FINE baselines (17,041 and 1,873 within 1%). The two COARSE baselines do not: measured 3,532 against
# 3,578 (-1.3%) and 2,160 against 2,089 (+3.4%). A coarse triangulation has proportionally fewer
# facets, so the same last-place libm differences move more of them, and 1% is tighter than the
# mesher's own cross-platform reproducibility at that deflection. The fix is a wider tolerance on the
# two coarse figures, which is a change to an Apple-platform test and belongs in its own PR.
"deflection is honoured, a coarser mesh draws fewer outline edges and more sharp ones"  # coarse mesh baseline vs a different libm
fullCircleOriginMatchesPriorBaseline()  # exact-equality baseline vs a different libm
offsetArcMatchesPriorBaseline()  # exact-equality baseline vs a different libm
unitOriginMatchesPriorBaseline()  # exact-equality baseline vs a different libm
offsetTiltedMatchesPriorBaseline()  # exact-equality baseline vs a different libm

# harness and are fixed in `Scripts/wasm-test-node-runner.mjs`: `readHome()` (the guest had no HOME)
# and `tempDirectory()` / `createAndRemoveDirectory()` (the shim reports 0 rights on a directory, so

# itself implements `path_remove_directory`). Five remain, each because the facility the OCCT wrapper
# reaches does not exist on this target and the wrapper answers rather than refusing. Each is measured, and #3025 holds the open question, which is a decision per row rather
