# OCCTCurveTests batch 3, laws-fitting: the injection matrix

Evidence for the PR that lifted 6 test files off `v5.0.0-766-execution` (source PRs #2648, #2647, #2611, #2591).
Measured against the pinned kernel `v4.0.0-kernel.5`; re-derive rather than quote. This directory is
scoped to this PR: `files.txt` lists its 6 test files, `reachable-funcs.py` derives the bridge entry
points they reach (`funcs.txt`, 47 names), and `generate-shadow.py` writes the switches for them
(`switches.txt`, 165 per test target).

| file | what it is |
|---|---|
| `reachable-funcs.py` | over-approximates the bridge entry points the PR's tests reach (the Swift declarations of every name a test calls, plus the `init` bodies of the types it builds), minus any symbol a test file calls itself through `import OCCTBridge`, which cannot be shadowed |
| `generate-shadow.py` | reads the C declaration of each and writes a module-local Swift function with the same name and signature, calling the real one and distorting its answer when `CRV_SWITCH` names a switch: a Bool inverted, a reference dropped, a scalar offset or negated, a count off by one or zeroed or short by one, one out parameter or struct field offset or negated, a Double input offset, a Bool input inverted. Entry points with an out-pointer-to-pointer or array-of-handles parameter cannot be mapped and are skipped (the script prints them) |
| `run-injection-matrix.py` | runs the built test bundle per switch through `swiftpm-testing-helper` for the PR's suites, derives the changed-test set from `git diff origin/main`, and reports both directions |
| `matrix-before.json`, `matrix-after.json` | `origin/main`'s versions of the 6 files, and the lifted ones; one line per switch that reddened a test or crashed |

Running it (repo root): `python3 <this dir>/generate-shadow.py --out Sources/OCCTSwift/InjectionShadow.swift
--switches <this dir>/switches.txt --funcs <this dir>/funcs.txt` (the output is never committed; add it to
`.git/info/exclude`), build the test target(s), symlink `XCTest.framework`, `Testing.framework` and
`libXCTestSwiftSupport.dylib` into `.build/out/Products/Debug/PackageFrameworks`, then `python3 <this
dir>/run-injection-matrix.py after --files <this dir>/files.txt`. For `before`: `git checkout origin/main --
$(cat files.txt)`, rebuild, run with label `before`, then `git checkout HEAD -- Tests`, delete the shadow,
rebuild and require `strings <bundle> | grep -c CRV_SWITCH` to read 0 and a run with a switch set to stay
green. `switches.txt` and `funcs.txt` are regenerated by the two scripts; they are committed so the
measurement can be re-run without re-deriving them. This batch measured the four sibling PRs from one build
whose shadow covered the union of their entry points; only this PR's switches were set, so the others were inert.

## Result

20 tests changed against `main` (a test is changed when its body differs or it does not exist there).

| | changed tests reddened by some switch | switches that redden a changed test |
|---|---|---|
| `main`'s versions | 14 of 20 (13 without crashing rows) | 8 |
| lifted | **19** of 20 (19 without crashing rows) | 46 |

Every switch was run; every baseline (no switch) was green on both sides. A crash (exit < 0 or > 1)
is named in the JSON (`crashes`: 3 before, 1 after) and is not a red row.

On `main`'s versions these changed tests catch nothing: CurveInterpolationTests.interpolateTooFewPoints, FairCurveBattenTests.battenCurveProperties, FairCurveMinimalVariationTests.withCurvatureConstraints, LawCompositeTests.compositeLaw, LawInterpolateTests.interpolatedEndpoints, LocOpeCurveShapeIntersectorTests.lineIntersectsBox.
After the lift the changed tests no switch reddens: CurveInterpolationTests.interpolateTooFewPoints.

`CurveInterpolationTests.interpolateTooFewPoints` is counted as changed only because the lift removes one blank line from its body. It is a refusal made by a Swift `guard points.count >= 2` before any bridge call, so no bridge shadow can redden it, on `main` or after; it is not a gain and the lift claims none for it.
