  The curve carries its own range, and it is a HALF-line: parameter 0 is the
  midpoint of the pair and negative parameters run off the curve. So the shipped
  [-100, 100] spends half its width off the curve and caps the live half at 100,
  and neither number has any relation to the caller's four points.


PART 2  is the domain an input to the intersection or a filter on its output?

  Read first, then measured. Bisector_Inter::Perform clips each of the basis curve's
  continuity intervals against the domain's parameter range, SKIPS any interval that
  does not overlap it, and hands the clipped sub-domain to Geom2dInt_GInter. It also
  reads D.FirstTolerance()/LastTolerance(), which raise Standard_DomainError on a
  domain with no first/last point. So it is an input, and an unbounded domain is not
  spelled IntRes2d_Domain(). The timing below is the cost question that follows.
