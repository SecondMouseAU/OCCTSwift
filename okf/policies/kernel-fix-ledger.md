# The kernel-fix ledger

OCCTSwift ships two kernel flavours (`docs/v4.0.0-plan.md`, family E). **Carry**, the default, is OCCT
plus the patches in `Scripts/patches/`. **Vanilla**, the opt-in LTS flavour, is OCCT exactly as
tagged (plus, on wasm only, the WASI port patches). They hold different sets of fixes, so "is this
defect fixed in the kernel?" has two answers, and a bridge guard written for a defect is needed on
one and dead code on the other.

Before the ledger that question was answered from memory. Three mitigations outlived their fix that
way (`okf/references/known-occt-bugs.md`, "Retired at the `v4.0.0-kernel.1` repin"), because no test
could say a guard had stopped being needed.

## The rule

1. **One row per defect** in `Scripts/kernel-fixes.tsv`. The column definitions and the meaning of
   "present" are in that file's header and in `Scripts/kernel_fixes.py`; they are not restated here.
2. **A guard written for a kernel defect** carries the tag `kernel-defect: F0080` and is compiled in
   only where the kernel lacks the fix:

   ```objc
   // kernel-defect: F0080 (IntTools_FaceFace::Perform on a face with no surface)
   #if !OCCTSWIFT_KERNEL_HAS_F0080
   if (!occtFaceHasSurface(face)) return false;
   #endif
   ```

3. **A test that needs the fix** says `requiresKernelFix("F0080")`. A test whose fault kills the
   process cannot be a known issue, so on a kernel without the fix it is skipped, not expected to
   fail.
4. **A guard the bridge can write for BOTH flavours is unconditional.** The `#if` is for a guard that
   exists only because the kernel lacks a fix; where the guard is also correct on a kernel that has it
   (a null-handle check, `if (result.isParallel)`), write it plainly and keep it. Prefer a bridge guard
   to a kernel patch wherever one is possible, since it protects both flavours.
5. **Each kernel asset carries `OCCTKernelFixes.h`**, generated by the build from the ledger
   (`Scripts/emit-kernel-fixes-header.py`). The bridge includes it when `__has_include` finds it; a
   kernel built before the ledger has none, every `OCCTSWIFT_KERNEL_HAS_Fxxxx` reads as 0, and every
   guard compiles in, which is the safe default.

## The gate

`Scripts/check-kernel-fixes.py` fails when:

- the ledger and `Scripts/patches/` disagree (a patch with no row; a row whose patch is gone and which
  no upstream release holds; an absorbed row whose file is still there);
- a tag, macro or test trait names a fix with no row;
- a guard's `#if !OCCTSWIFT_KERNEL_HAS_Fxxxx` names a fix **every shipping flavour holds**, which means
  it can never compile in: **retire this guard**. Delete it and its tag, and keep the regression test
  that fails if it comes back.

## Retirement is per flavour

- **Carry** retires a guard at the repin that carries the patch, as #3533 did by hand.
- **Vanilla** retires it when the OCCT version the vanilla kernel is built from reaches the release
  that contains the fix. For a fix upstream never backports to 8.0.x that is the next major, which is
  the recurring cost of the LTS flavour.
- A guard that was retired because the carry kernel holds the fix is **reinstated** under `#if` for
  the vanilla flavour, from git history, in the same change that adds the vanilla kernel.

## When upstream takes a patch (ours or someone else's)

| What upstream did | Action |
|---|---|
| Identical or same code as ours | Retire ours; the row becomes `absorbed`, gains `upstream_in`, and the relation |
| A different form, same result | Retire ours, take upstream's, re-measure our suite |
| A different behaviour | Take upstream's; the bridge adapts; relation `different-behaviour`; a SEMVER row if an answer flips |
| Touched nearby, ours still needed | Rebase by three-way merge against the patched tree |
| Covers half of ours | Never carry the surviving half. Keep ours whole, or drop it whole and file the gap |
| Someone else has an open PR for the same defect | Do not submit a duplicate: test theirs and carry ours until theirs lands |

`Scripts/survey-upstream-release.sh <tag>` produces this verdict table for a new upstream release.
