# WASI patches are authored against the carried-patch tree

**The rule.** A patch in `Scripts/patches-wasi/` is generated by `git diff` in
`Libraries/occt-src` **after** everything in `Scripts/patches/` is applied, and verified by
`git apply --check` in that same state. A patch that applies to vanilla but not to the patched
tree, or the reverse, is a defect.

This is about the state a patch is **authored and checked** in. The order it is applied in was
never in question: `Scripts/build-occt-wasm.sh` has always applied the carried set first and this
directory second.

## Why it matters, and how it was missed

PR #2076 authored fifteen WASI patches against a pristine `V8_0_1` and verified them by applying
them to one. The green check on that PR read "all 14 patches apply cleanly", which was true and
measured the wrong tree.

What that hid is that the carried set is not a thin layer. Nine carried patches inject
`std::mutex` and `std::recursive_mutex` into OCCT (#341, #344, #349, #353, #374, #1153, #1154,
#1157, #1403). The Swift wasip1 SDK ships a libc++ with `_LIBCPP_HAS_THREADS 0`, so every one of
those is a file the WASI build has to answer for, and **15 of the 76 threading-dependent files in
the four modules this build compiles are files we patch ourselves**. Authored against vanilla,
none of that is visible: the patch author sees an OCCT that does not use `std::mutex` in those
files at all.

The same argument applies to every carried patch, not only the threading ones, and it gets
stronger at each kernel repin: patches are added, retired (0032 was, unshipped) and renumbered, and
a WASI patch cut before that happened is verified against a tree nobody builds.

## What to do when writing one

```bash
cd Libraries/occt-src
git checkout .                                   # a clean V8_0_1
for p in ../../Scripts/patches/*.patch; do git apply "$p"; done
# ... make the WASI change ...
git diff -- src/path/to/File.cxx > ../../Scripts/patches-wasi/wasi-<thing>.patch
git apply --check ../../Scripts/patches-wasi/wasi-<thing>.patch   # in THIS state
```

Keep the `diff --git` and `index` header lines that `git diff` emits. The `index` pre-image blob
is the exact identity of the tree the patch was cut from, and it is the only part of a patch that
says so without ambiguity. The two patches in the directory today were hand trimmed and have no
`index` line, which is why its absence is not a defect; it is a weaker patch, not a wrong one.

Then add the patch's row to [`Scripts/patches-wasi/README.md`](../../Scripts/patches-wasi/README.md),
which `check-inventory-prose.py` gates.

**If the file is one a carried patch also touches**, declare it, one line per carried patch, in the
patch preamble:

```
Applies-After: 0033-Interface_Static-thread-safety-mutex-1157.patch
```

That line is not paperwork. It is the record that somebody regenerated the diff in the patched
state, and it is what fails loudly at the next repin: when the carried patch is retired or
renumbered, the trailer stops resolving and the WASI patch has to be re-verified, instead of
silently sitting on a state that no longer exists.

## What the gate can and cannot check

`Scripts/check-wasi-patch-base.py` runs in `ci.yml`'s `gate-scripts` job, which is pure Python over
the repo's own text: no OCCT, no `Libraries/occt-src`, no build, no network, and it
[must not grow one](static-gates.md). `git apply --check` is not reconstructible from text, so the
gate checks every way the two patch sets can contradict each other instead:

| Rule | What it proves |
|---|---|
| `CARRIED_COLLISION` | a WASI patch and a carried patch edit one file, and the WASI patch declares no `Applies-After:` |
| `STALE_TRAILER` | an `Applies-After:` naming a carried patch that is gone, or that does not touch the file |
| `STALE_CONTEXT` | a WASI context line that the carried set deletes from that file, so the diff was cut from vanilla |
| `FOREIGN_MEMBER` | an added line using an OCCT `my<Name>` member no context shows and no added line declares |
| `COINCIDENT_TARGET` | two WASI patches editing one file, whose relative order nobody decided |

**Stated plainly, it cannot run `git apply --check`.** A WASI patch whose context does not exist in
the patched tree, for a file no carried patch touches, is invisible to all five rules, and so is
one whose hunk offsets have drifted. Those need a checkout.

`--tree DIR` (default `Libraries/occt-src`) is that mode and it is the real check: it requires
every carried patch to be applied in `DIR`, verifies each WASI patch's `index` pre-image blob
against `git hash-object` of the target in that state, and runs `git apply --check`. It is
**not** part of `gate-scripts`, and per #2098 a mode that examined nothing must fail rather than
pass, so `--require-tree` turns a missing or unpatched tree from a printed note into an error. The
wasm build job is where it belongs, alongside
`check-preprocessor-balance.py --tree --require-tree`.

## The patch that motivated the rule is not a patch-base defect

Worth writing down, because the one-line version of #2168 is misleading. PR #2076's
`wasi-osd-directory.patch` regressed `OSD_Directory::BuildTemporary` from the `mkdir` form to an
`open()` form. Its base was correct, measured three ways: its `index` line names the real `V8_0_1`
blob, it applies cleanly to both the pristine and the carried-patched tree, and applying it
reproduces the post-image blob its own `index` line claims.

What is wrong with it is that its added code is `OSD_File`'s, pasted into `OSD_Directory`:

```
+  myFileChannel = open(aTmpName2, O_CREAT | O_EXCL | O_RDWR, 0600);
```

`OSD_Directory` has no `myFileChannel`. The wrong thing was the **file**, not the tree, and no
base-state check of any kind can see it. That is what `FOREIGN_MEMBER` is for, and over the whole
fifteen-patch #2076 corpus it reports exactly one member and nothing else.

The general lesson is the one `check-preprocessor-balance.py` already carries: "the patch applies
cleanly" is a narrow claim, and each of the three properties #2076 got wrong (it preprocesses, it
was cut from the right tree, it edits the class it names) needs its own check.
