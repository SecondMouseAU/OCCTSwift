## Finding

During Epic #766 Phase 3 verification of Issue #603 (CPnts_AbscissaPoint single quadrature fix), we injected the defect by removing the adaptive quadrature loop in `occtArcConvergedLength()` (returning single quadrature instead of iterative halving until convergence).

**Expected**: Tests should fail (Red) because the single quadrature introduces arc-length errors up to 1.7% (ellipse) / 3% (parabola) as documented in the kernel fix.

**Actual**: All 15 tests (Issue603SingleSpanQuadratureTests) passed (Green).

## Details

- **Injection**: Modified `occtArcConvergedLength()` in `Sources/OCCTBridge/src/OCCTBridge_Internal.h` to return single quadrature immediately:
  ```cpp
  // Injected defect
  pieces = 1;
  return occtArcQuadrature(adaptor, lo, hi, singleSpan);
  ```

- **Tests run**: `Issue603SingleSpanQuadratureTests` (15 tests, whole ellipse, parabola, hyperbola, Bezier, sub-ranges, 2D ellipse, edge, wire, EdgeCurve, parameterAtLength)

- **Tolerance used**: 1e-9 relative (from `kOCCTArcLengthTolerance`)

- **Independent references**: Tests use Richardson-extrapolated chord sum and Simpson quadrature as ground truth

## Hypothesis

The test's independent reference calculations (Richardson-extrapolated chord sum / Simpson quadrature) may be measuring the same single-quadrature result that the injection produces, because:

1. The injection returns the same `occtArcQuadrature()` result that the reference uses
2. The convergence loop was meant to refine beyond single quadrature, but tests compare against a reference that also uses single quadrature
3. The 1e-9 tolerance is relative to the *result*, not an absolute ground truth
